## Approach

Every case follows the same structure:
1. **Assumptions:** what isn't specified, what I assumed, and what changes if I'm wrong
2. **Architecture:** one diagram, with the stack named on each component
3. **Why:** a short justification for each choice
4. **Trade-offs and risks:** what each choice costs, and how it's mitigated
5. **Delivery:** how the work gets done within the constraints
